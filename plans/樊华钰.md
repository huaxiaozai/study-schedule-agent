# 樊华钰 · 前端开发计划

> 负责模块：前端（Vue 3 + TypeScript + Vite + Element Plus + FullCalendar + Axios）
> 更新时间：2026-10-10

## Global Constraints

- 初版周期五周，每周建议投入 8–10 小时。
- 时间槽粒度固定为 30 分钟，默认时区 Asia/Shanghai。
- 前端类型必须与熊翔维护的四个稳定契约（ImportProposal / ScheduleSnapshot / ActionSpec / ProfileFact）字段一一对应。
- API 路径统一 `/api/v1/`，返回统一成功/错误结构。
- 初版不引入 Pinia，跨页面状态用组合式函数；状态明显增多时再引入。
- 页面必须区分处理中、待补充、待确认、已执行和失败五种状态，不能把处理中显示为成功。
- 批量移动、取消或影响其他任务的动作必须显示预览并由用户确认。
- 前端类型检查使用 `vue-tsc`，关键工具函数可使用 Vitest。

## Task 4 Agent 动作预览与确认交互

**预计工时：8–10 小时**

### Files

- Create: `frontend/src/components/ActionPreview.vue`
- Create: `frontend/src/components/ActionConfirmDialog.vue`
- Create: `frontend/src/composables/useActionSpec.ts`
- Create: `frontend/src/api/agent.ts`

### Consumes

熊翔交付的 ActionSpec 契约和 ActionStatus 枚举；黄健华交付的动作执行 API。

### Produces

动作预览卡片；批量操作二次确认；执行回执展示。

- [ ] Agent 返回 ActionSpec 后，以预览卡片展示：操作类型、目标任务、变更内容、影响范围
- [ ] 批量移动/取消动作必须弹出二次确认对话框
- [ ] NEEDS_CONFIRMATION 状态高亮提示用户确认
- [ ] 执行后展示回执：成功 / 失败 / 冲突
- [ ] 失败时显示 reasonFacts 原因说明
- [ ] 状态映射：处理中 / 待补充 / 待确认 / 已执行 / 失败，与后端 ActionStatus 枚举一一对应
- [ ] 过期 baseRevision 时提示日程已变更，需重新生成

**验收：** 生成排程 → 预览 → 确认写入 → 日历刷新全流程走通；冲突时显示原因不直接写库；过期版本返回 409 时前端正确提示。
